# 천년가문 v0.1

1392년의 가상 인물로 시작하여 가문 단절 또는 2026년까지 플레이하는 한국어 웹 시뮬레이터입니다. 실제 족보를 생성하거나 실제 가문의 역사를 재현하지 않습니다.

## 실행

Node.js 22.17 이상 권장. Windows PowerShell에서는 `npm.cmd`를 사용하면 실행 정책 변경 없이 실행할 수 있습니다.

```powershell
git clone https://github.com/im209/thousand-lineage.git
cd thousand-lineage
npm.cmd ci
npm.cmd run dev
```

브라우저에서 http://127.0.0.1:5173 을 엽니다.

```powershell
npm.cmd test
npm.cmd run build
npx.cmd playwright install chromium
npm.cmd run test:e2e
```

`dist`는 정적 배포 결과입니다. 백엔드·API 키가 필요하지 않습니다.

macOS/Linux에서는 같은 명령의 `npm.cmd`를 `npm`, `npx.cmd`를 `npx`로 바꿉니다. Node.js 22.17 이상과 Git을 설치한 뒤 실행하세요. Claude Code를 사용할 때는 복제한 `thousand-lineage` 폴더에서 시작하면 `CLAUDE.md`의 프로젝트 안내를 읽을 수 있습니다.

작업을 시작하기 전에 `git pull --ff-only`, 수정 후 `git add .`, `git commit -m "변경 내용"`, `git push`로 두 컴퓨터의 소스를 동기화합니다. 게임 진행과 결말 수집은 각 브라우저의 localStorage에 저장되므로 GitHub로 동기화되지 않습니다. 연대기 JSON 내보내기는 기록 보관용이며 현재 게임에 불러오기 기능은 없습니다.

## GitHub Pages

저장소: https://github.com/im209/thousand-lineage

Pages 활성화 후 사용할 주소: https://im209.github.io/thousand-lineage/

저장소 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 한 번 선택합니다. `.github/workflows/deploy.yml`이 `main`에 올린 코드를 검사·빌드·배포합니다. 처음 활성화한 뒤에는 Actions에서 `Deploy game to GitHub Pages` → `Run workflow`를 누르면 됩니다. 비밀키나 별도 API 설정은 필요하지 않습니다. Pages 사이트 공개 여부는 저장소 Settings에서 확인합니다.

Vite의 `base: './'`로 프로젝트 하위 경로와 일반 도메인 모두에서 정적 파일을 읽습니다. 이후 새 도메인을 구매하면 Pages 설정과 DNS를 추가할 수 있습니다. 구매는 보류 중입니다. 상세 규칙은 [Vite 공식 배포 안내](https://vite.dev/guide/static-deploy.html#github-pages)를 참고하세요.

## 게임성 설계

[게임성 벤치마크](docs/GAMEPLAY-BENCHMARK.md)에 Cookie Clicker·2048·A Dark Room의 1차 자료와 적용 판단을 정리했습니다. 흥행 원인이나 실제 플레이어 유지율을 측정한 결과는 아닙니다.

과업은 한 번에 하나를 진행하며 바꿔도 진행도가 남습니다. 배움은 교육 55, 상업은 연결 55, 돌봄은 결속 65와 관련 선택 3회가 필요합니다. 보상은 현재 생존한 가족에게 적용되며, 완료한 과업의 특별 선택은 해당 게임 전체에 유지됩니다. 새 게임에서 능력 보너스를 상속하지 않습니다. 성씨에 따른 보너스는 없습니다.

새 게임의 출발 신분은 성씨·본관과 무관하게 네 배경 중 같은 확률로 배정됩니다. 신분 추첨은 시드로 재현되며 가족 생성용 난수 흐름과 분리합니다. 기존 저장의 신분은 다시 추첨하지 않습니다. 같은 시드 재도전은 창시자의 기존 출발 신분과 조건을 재현합니다. 다른 선택은 이후 난수 흐름과 가족·사건을 바꿀 수 있습니다. 최고 기록은 브라우저별로 저장되며 서버 순위표가 아닙니다.

[조선 신분·정치 모델](docs/JOSEON-SYSTEM.md)에 법적 양천 구분, 양반 형성, 과거 자격, 1801년과 1894년의 차이와 근거를 정리했습니다. 가문 단위로 요약하는 게임이며 개인별 신분 상속·서얼·직역별 자격을 모두 재현하지 않습니다. 출발 배경과 확률·수치의 차이는 설계값이며 인구 분포가 아닙니다.

대체역사 분기는 실제 연표가 그대로 발생했다고 서술하지 않습니다. 이후 역사 사건을 참고 배경으로 표시하고, 1894년 근대 전환만 모든 경로에 공통 적용하는 게임 규칙으로 둡니다. 한 가문의 행동으로 세계 전체의 역사를 다시 계산하는 모델은 아닙니다.

[조선 생활사 확장 근거](docs/JOSEON-EXPANSION-SOURCES.md)에 구휼·의술·기록·장시·피난·분재의 자료와 시대 경계를 정리했습니다. 장시는 1500년부터, 전란·재건은 1592–1660년, 다른 생활 경로는 1392–1893년에 준비·완수할 수 있습니다. 개인 상속 계산은 균등 분배를 유지하며 분재 사건은 가족 합의와 문서에 관한 서사입니다.

엔딩 우선순위는 계보 단절 → 복합 성취 → 창업·복귀·옹립 → 가장 최근 완수한 조선 생활사 → 신분 → 돌봄·상업·배움 과업 → 일반 생존입니다. 생존 엔딩은 후손이 2026년까지 이어져야 수집합니다. 한 회차에 대표 결말 하나만 수집하며, 다른 성취도 해당 가문의 저장 기록에 보존합니다. 생활사의 같은 결과를 두 번 얻을 수는 없지만 같은 갈래를 다시 준비해 다른 결과를 완수할 수 있습니다.

Vitest: 100개 시드를 단절/2026년까지 자동 플레이하여 부모 자녀 상호 관계, 부모 연령, 생몰연도, 배우자 관계, 생존 상태, 종료 연도와 엔딩을 검사합니다. 동일 시드·선택의 재현성, JSON 저장 복원, 잘못된 계승 차단, 종료 후 진행 차단, 역사 시기와 세대 방향도 검사합니다.

Vitest에는 부채·미성년 직업·잘못된 저장·대표 순번·개별 교육·성인 후보 우선·보호 비용 및 전체 공개 목록 수록·기존 ID 보존·신규 성씨 저장 복원 검증도 포함됩니다. 과업 보상 중복 방지, 선택 잠금, 능력 조건, 기존 저장 호환, 기록장 손상·저장 실패·동일 실행 중복도 검사합니다.

Playwright: 1440px 데스크톱과 390px 모바일에서 검색 더 보기·한자 검색·본관 미공개 성씨 시작·선택·결과 저장 복원·후계자 비교·가계도·연대기·저장 실패 및 백업 복원을 검증합니다. 과업 선택·보상·해금 조건·초반 5년 진행과 같은 시드 재도전 시 초기화·기록 보존도 검사합니다. 인물 모달 Escape 닫기와 가로 넘침, 런타임 오류도 확인합니다. 화면 캡처는 `test-results`에 생성됩니다.

`node scripts/balance-check.cjs 30`은 30개 시드를 다섯 가지 자동 선택 정책으로 플레이하고 `docs/balance-results.json`에 생존·과업·부채 결과를 기록합니다. 작은 결정적 표본과 휴리스틱 전략이므로 사람의 재미나 최적 전략의 우열을 입증하지 않습니다.

## 제한 및 다음 버전

- 게임의 혼인 연령·출생·사망·상속 모델은 밸런스용 가정입니다. 실제 인구 통계나 시대별 법률의 재현이 아닙니다.
- 계승 후보는 창시자의 모든 생존 후손입니다. 전임 대표와 방계 관계일 수 있으므로 혈연 세대와 대표 순번을 분리합니다. 양자 및 정교한 시대별 상속 규칙은 미구현입니다.
- 개인 재산은 사망 시 생존 자녀에게 균등 분할합니다. 공동 재산과 부채는 시대 내 게임 지표이며 실제 재산 가치가 아닙니다.
- 인구 급증을 피하기 위해 생존 인원에 따른 출생 확률 감쇠를 사용합니다. 생존 인원 상한으로 인물을 삭제하지 않습니다.
- 긴 플레이의 성능과 극단적 시드는 추가 검증 대상입니다. 목표 플레이 시간 15–25분은 사용자 플레이테스트로 아직 검증하지 않았습니다.
- 일부 역사 사건은 공통 선택지를 공유합니다. 시대별 직업·지역명, 세부 신분 상속, 장기 밸런스와 상속법 고증은 추가 확장 대상입니다.
- 아케이드 돌발 이벤트, 계정·클라우드 저장, JSON 가져오기는 없습니다. 브라우저 저장 데이터 삭제 시 진행이 사라집니다.

## 코드 구조

- `src/engine.ts`: 난수·인물·가계·시간·사건·계승·엔딩
- `src/data.ts`: 검증 조합·출처·역사/생활/세대 사건·시대·직업
- `src/clan-census.json`, `scripts/import-clans.mjs`: 공개 성씨·본관 데이터와 재생성 스크립트
- `src/store.ts`, `src/save.ts`: 게임 상태, 저장 구조 검사와 백업
- `src/life-events.ts`: 고유 생활 사건
- `src/projects.ts`, `src/progression-panels.tsx`, `src/progression.css`: 가문 과업·조건부 선택·진행 UI
- `src/records.ts`: 최고 기록·최근 엔딩 저장과 오류 처리
- `src/society.ts`, `src/society-panels.tsx`, `src/society.css`: 출발 신분·관직·정치 분기·근대 전환과 화면
- `src/chronicles.ts`, `src/chronicle-panels.tsx`, `src/chronicles.css`: 조선 생활사 6갈래·12결과, 두 단계 사건과 결말 도감 화면
- `src/endings.ts`: 26종 결말의 누적 성취 판정과 조건·힌트
- `src/main.tsx`, `src/game-panels.tsx`, `src/person-dialog.tsx`, `src/family-tree.tsx`: 화면과 가계도
- `src/bright.css`: 밝은 디자인과 반응형 레이아웃
- `src/engine.test.ts`, `e2e/`: 검증

추가 사건은 데이터에 추가하며, 미래의 아케이드 사건은 `kind: 'arcade'`로 구분할 수 있습니다.
